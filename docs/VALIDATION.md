## v0.4.10 잠금 없는 입력 누락 감지·자동 복구 (2026-10-15)

실제로 실행 중인 0.4.9에서 Windows 잠금 없이 클릭·잡기 무반응이 재발했습니다. 09:19:36부터 Windows는 펫 몸 위의 누름을 관찰했고 창은 표시·입력 허용·최상단·클릭 통과 해제 상태였지만, 해당 시도의 Electron `mouseDown`과 화면의 잡기 시작 요청은 없었습니다. 일부 `mouseUp`·화면 해제 이벤트와 이동·대사·상태 기록은 계속됐습니다. 중간에 한 번 잡기가 전달된 뒤 다시 누락됐으므로 전체 프로세스 정지로 판정하지 않습니다. 사용자는 잠금하지 않았고 테마만 바꿨을 수 있다고 답했습니다. 테마 변경이 원인이라는 증거와 Electron/Windows 내부의 정확한 발생 원인은 아직 확보하지 못했습니다.

사용자가 트레이 **펫 입력 복구** 후 정상 클릭·잡기를 확인했습니다. 실제 로그에도 09:26:10 복구 요청 → 09:26:11 새 창 ID 3/세대 2 준비 → 09:26:12와 09:26:14의 `electron.mouse(mouseDown)` → `renderer.handler.down` → `ipc.drag(start)` 및 놓기가 연결됩니다. 원본은 로컬 `artifacts/input-capture-20261015-092025/`에 보관하며 Git에 올리지 않습니다.

0.4.10은 펫 위에서 관찰한 네이티브 누름·해제와 실제 잡기 시작 응답을 비교합니다. 누름 전 몸 위의 해제 상태를 먼저 관찰해야 하며, 지연된 화면 응답을 300ms 기다립니다. 15초 안에 응답 없는 시도가 두 번 이어지면 버튼을 놓은 뒤 펫 창을 새로 만들고 위치·창 위 착지·작은 볼·성장·설정과 관리 화면을 유지합니다. 자동 교체는 최소 30초 간격으로 제한합니다. 정상 잡기는 대기 증거를 취소하고, 투명 여백·다른 창/캡처·숨김·이전 HWND·크기 전환·종료 중 신호는 제외합니다. 물리 픽셀은 샘플의 창 크기로 변환하며 서로 다른 모니터의 배율을 가정하지 않습니다.

추가 로그는 `input.delivery-missed`, `input.auto-repair`와 펫 자신의 정해진 Windows 메시지 이름입니다. 원문 메시지 버퍼·다른 창 핸들·대화·키보드 입력을 추가로 수집하지 않습니다. 짧은 클릭이 네이티브 120ms 샘플링에 잡히지 않으면 그 시도는 자동 복구 판단에 사용하지 않습니다.

## v0.4.1 클릭·잡기 입력 진단 (2026-10-07)

실제 사용 중인 0.4.0에서 클릭·잡기 무반응을 관찰했습니다. 프로세스는 응답하고 이동 일시정지는 꺼져 있었으며, 펫 위에 커서를 올렸을 때 Windows의 클릭 통과 플래그가 해제되고 커서 아래 창이 펫으로 판별됐습니다. 당시 실행 파일에는 화면 이벤트 추적 로그가 없어 어느 단계에서 중단됐는지 확정하지 못했습니다. 사용자의 실행 중인 앱·저장 상태를 변경하지 않고 조사했습니다.

## 자동화 범위

`npm test`는 실제 SQLite 트랜잭션과 고정 사용량 기록을 검증합니다. 모니터 제거·절전·드래그 좌표·클릭 통과 API 호출은 모의 OS 이벤트로 검증합니다.

`npm run smoke`는 Electron 앱을 실제 실행해 화면과 IPC, 재시작 후 사용량을 확인합니다. `npm run smoke -- --live`는 현재 컴퓨터의 실제 로그로 별도의 읽기 검증을 수행합니다.

`npm run smoke:pet`는 임시 로그로 부화한 펫과 9종의 화면을 검증합니다. Playwright 포인터 이벤트로 잡기·놓기·클릭을 수행하고, 실제 Electron 창 좌표를 연속 측정해 낙하를 확인합니다. 테스트 앱 안에서만 커서 좌표를 대체하며 OS의 실제 커서는 이동시키지 않습니다. 결과는 `artifacts/pet-motion-report.json`, 화면은 `artifacts/pet-held.png`, `artifacts/pet-falling.png`, `artifacts/pet-landing.png`에 생성됩니다. `POKETOKEN_EXE`를 지정하면 Windows·Mac 패키지 앱에도 같은 검증을 수행합니다.

v0.2.1에는 잠금 복귀 회귀 검사를 추가했습니다. 커서가 펫 위에 그대로 있는 상태에서 입력이 복구되는지, 투명한 여백은 클릭을 통과시키는지, 잠금과 절전이 겹치면 둘 다 해제될 때까지 숨기는지, 잡고 있던 포인터 캡처를 해제한 후 다음 드래그가 가능한지 확인합니다. 테스트 앱 안에서 `powerMonitor` 이벤트를 발생시키고 실제 Electron 마우스 전달 API 호출을 관찰합니다. 사용자 컴퓨터를 자동으로 잠그거나 절전시키지는 않으므로 물리 잠금·해제 확인은 별도로 필요합니다.

v0.3.0의 `npm run smoke:windows`는 별도 Electron 프로세스의 실제 외부 창을 만들고, Windows의 Win32/DWM 또는 Mac의 Core Graphics 보조 프로세스가 반환하는 좌표로 검증합니다. 창의 위치·크기·식별 정보만 사용하며 창 이름과 화면 내용은 수집하지 않습니다. 테스트에서 만든 창의 PID만 사용하도록 테스트 앱을 제한하고, 임시 데이터 폴더에서 착지·걷기·이동·크기 변경·가림·최소화·종료를 확인합니다. 포인터는 `smoke:pet`과 같은 자동화 방식입니다. 결과는 `artifacts/window-motion-report.json`, 화면은 `artifacts/pet-on-window.png`에 생성됩니다. 일반 `smoke`·`smoke:pet` 검사는 주변의 실제 창이 낙하에 영향을 주지 않도록 테스트 모드에서 창 감지를 끕니다. 창 전용 검사에서만 실제 네이티브 감지를 활성화합니다.

창 위에 펫과 말풍선이 들어갈 공간이 있어야 착지할 수 있습니다. 화면 맨 위에 붙은 창, 너무 좁은 창, 가려진 테두리는 착지면에서 제외합니다. 모니터를 넘기는 창 추적·캐릭터 크기 변경·모니터 제거·잠금 복귀 시 부착 해제는 단위 테스트로 확인했고, 물리 듀얼 모니터·혼합 배율 검증은 별도로 남아 있습니다.

`npm run smoke:portable`은 Windows portable 실행 파일을 실제 실행해 패키지에 들어간 리소스와 네이티브 모듈, 부화, 이미지 표시를 검증하고 펫 캡처의 배경 알파값도 확인합니다. 테스트는 고유 디버깅 포트와 임시 데이터 폴더를 사용하며 해당 테스트 프로세스만 종료합니다.

## 남은 실기 확인

- Windows에서 다른 앱 위의 실제 마우스 클릭 통과·드래그와 키보드 포커스를 확인합니다. 자동 테스트에서는 창의 비활성 표시·포커스 불가 속성과 마우스 전달 API 호출을 확인했습니다.
- 실제 듀얼 모니터 연결/분리, 125%·150%·200% 화면 배율, 잠금·절전 복귀를 확인합니다. 현재 결과는 좌표·이벤트 로직의 자동 테스트이며 물리 모니터 시험을 대신하지 않습니다.
- 자동 시작은 로그인 등록을 변경하므로 자동 테스트에서 켜지 않았습니다. 실행 파일을 유지할 위치에 놓고 설정을 켠 뒤 다음 로그인에서 확인합니다.
- Intel Mac은 아직 빌드·실행하지 않았습니다. 네이티브 Intel 러너에서 `Mac test build` 워크플로의 `x64` 옵션으로 같은 검증을 수행해야 합니다.
- Mac에서 투명 창, 메뉴바 아이콘, Spaces·전체 화면, 드래그·클릭 통과, 듀얼 모니터·절전 복귀를 확인합니다.
- 전달받은 DMG를 설치한 Mac에서 첫 실행 경고 처리와 실제 Claude Code·Codex 사용 후 성장·재시작을 확인합니다.

**Apple Silicon용 DMG 빌드와 Mac 러너에서의 패키지 앱 실행 검증을 완료했습니다. 물리 Mac 실기 확인과 Intel 검증은 아직 남아 있습니다.**
