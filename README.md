# PokeToken Desktop

Claude Code·Codex에 쓴 토큰으로 포켓몬을 키우는 윈도우·맥 데스크톱 펫입니다. 18가지 타입의 알과 예시 진화 계열 19개, 총 61종을 지원합니다. 도감 선택·개체별 성장 보관·경험치사탕·이로치 부화와 선택, 이브이의 8가지 분기 진화가 가능합니다.

## 실행

[v0.4.9 릴리스](https://github.com/KHLEE72/pokeTokenShimeji/releases/tag/v0.4.9)에서 Windows x64용 EXE, Mac M시리즈용 arm64 DMG, Intel용 x64 DMG를 받을 수 있습니다. Mac은 macOS 14 이상이 필요하며 [설치·실행 안내](docs/MAC_TESTING.md)를 참고하세요. 저장소가 비공개인 동안에는 다운로드에도 저장소 접근 권한이 필요합니다.

현재 소스의 윈도우 빌드 결과는 `release/PokeToken-Desktop-0.4.10-win-x64.exe`입니다. 실행하면 관리 화면과 화면 아래의 알이 나타납니다. 관리 화면을 닫아도 트레이에서 계속 실행됩니다. 완전히 종료하려면 트레이 메뉴의 **종료**를 선택하세요. 실행 파일은 Git에 포함하지 않으며 아래 패키징 명령으로 만듭니다.

기존 버전이 실행 중이면 트레이에서 종료한 뒤 새 실행 파일을 실행하세요. 같은 앱 데이터 폴더를 사용하므로 기존 성장·도감·설정은 유지됩니다.

개발 환경에는 Node.js 22.12 이상이 필요합니다.

```sh
git clone https://github.com/KHLEE72/pokeTokenShimeji.git
cd pokeTokenShimeji
npm ci
npm run dev
```

운영 빌드 실행과 검증:

```sh
npm run build
npm run start
npm test
npm run smoke
npm run smoke:pet
npm run smoke:windows
npm run smoke:dpi
npm run smoke:health
npm run smoke:collection
npm run smoke:evolution
npm run smoke:rewards
# Windows portable 파일을 만든 뒤에는 npm run smoke:portable
```

`npm test`는 Electron의 Node 런타임으로 실행하므로 Electron에 맞춰 빌드된 SQLite 모듈을 그대로 검증합니다. 설치에 사용하는 npm registry는 이 프로젝트의 `.npmrc`에서만 공개 npm으로 지정합니다.

## 사용법

- **현재 펫 · 사용량**은 알 보관함이 닫혀 있으면 최소 창 크기에서도 한 화면에 들어옵니다. 보관함은 부화 중인 알과 진행률이 높은 알을 최대 3개 요약하며 나머지는 펼쳐서 확인합니다. 도감 바로가기는 펫 카드 위쪽에 있습니다.
- 상단의 테마 버튼 또는 **설정 → 화면 테마**에서 테마를 선택합니다. **몬스터볼 라이트·보라시티 다크**는 기본 제공이며 다른 볼 테마는 업적으로 열립니다. 선택은 재실행 후에도 유지됩니다. 알 보관함·도감·설정처럼 긴 화면의 오른쪽 스크롤바도 테마에 맞춘 사각 픽셀 스타일을 사용합니다.
- 기본 로그 폴더에서 Claude Code·Codex 기록을 자동으로 찾습니다. 처음 연결한 기록은 사용량에만 표시하고 이후 새로 사용하는 토큰부터 성장합니다.
- 캐릭터를 짧게 클릭하면 하트와 쓰다듬기 동작, 캐릭터별 대사가 나옵니다. 관리 화면은 오른쪽 클릭 또는 트레이의 **현재 펫 · 사용량**에서 엽니다. 마우스로 집어 옮기면 놓은 위치 아래의 창 테두리나 화면 바닥으로 내려갑니다. 오른쪽 클릭과 트레이에서 숨기기·이동 일시정지·설정·종료를 사용할 수 있습니다.
- 잡고 움직이면 캐릭터가 매달려 흔들리고, 놓으면 그 높이에서 가속하며 떨어집니다. 착지할 때 살짝 눌렸다 튀며 쉬었다가 다시 걷습니다. 걷기를 일시정지해도 낙하는 마칩니다.
- 화면 잠금·절전 중에는 펫을 숨기고 잡기 상태를 해제합니다. Windows는 복귀 때 펫 전용 창과 입력 연결을 새로 만들고 준비가 끝난 뒤 포커스를 가져오지 않고 표시합니다. 성장·사용량·설정과 관리 화면은 유지합니다. 중복 알림은 한 번으로 합치고 숨겨 둔 펫은 숨김을 유지합니다.
- 실행 중 마우스 전달 상태를 0.75초 간격으로 다시 적용하고, 창 표시 순서는 1초 간격으로 복구합니다. 다른 ‘항상 위’ 창이 새로 나타나도 펫이 다시 앞으로 오며 작업 중인 앱의 키보드 포커스와 잡고 있는 포인터 캡처는 유지합니다. 숨김·잠금·절전 중에는 펫을 앞으로 올리지 않습니다.
- 펫을 창 위에서 놓으면 노출된 위쪽 테두리에 착지해 걷거나 쉽니다. 창을 옮기거나 크기를 바꾸면 따라가고, 최소화·종료하거나 다른 창에 가려지면 떨어집니다. 이동 일시정지는 창을 따라가는 동작에는 영향을 주지 않습니다.
- PokeToken 관리 화면과 카카오톡처럼 기본 제목 표시줄 대신 자체 제목 표시줄을 사용하는 창도 받침으로 사용할 수 있습니다. 펫 자신의 투명 창과 도구 설명·알림 팝업은 제외합니다.
- 창 위에 펫과 말풍선이 들어갈 공간이 있어야 합니다. 창이 화면 맨 위에 붙어 있으면 조금 아래로 옮긴 뒤 펫의 발이 테두리 근처에 오도록 놓으세요. 좁은 창·가려진 테두리는 착지면에서 제외됩니다.
- 알과 61종의 포켓몬은 평소·쓰다듬기·잡기·낙하·착지·성장·토큰 증가 상황에 맞는 대사를 랜덤으로 말합니다. 같은 상황에서 같은 문장이 연달아 나오지 않으며, 평소 대사는 약 35~65초 간격입니다. 토큰 반응은 최대 1분에 한 번입니다. 대사는 로컬 목록에서 선택하며 AI를 호출하지 않습니다.
- 설정에서 성장 속도, 96/128/192px 크기, 모니터와 자동 시작을 변경합니다. 자동 시작은 기본으로 꺼져 있습니다.
- 크기와 이동 좌표는 화면 배율에 맞춘 논리 픽셀을 사용합니다. 125%·150%에서도 펫과 대사의 비율을 유지하며, 드래그 후에는 마우스를 놓은 모니터의 작업 영역 안에 착지합니다. 관리 화면 확대는 펫에 적용되지 않습니다.
- 로그는 10초마다 확인하고 새 파일은 60초마다 찾습니다. **새로고침**은 새 파일도 즉시 탐색합니다.
- 없는 폴더는 오류 없이 기다리고, 불완전한 기록은 다음 변경 때 다시 읽습니다. 로그가 기록되지 않는 도구 사용은 집계할 수 없습니다.
- 기존 파일을 이동하거나 세션을 보관해도 동일한 사용량을 다시 경험치로 지급하지 않습니다. 앱을 꺼둔 동안의 새 사용량은 다음 실행 때 반영합니다.

## 업적·몬스터볼·테마 (0.4.9)

**업적 · 볼 컬렉션**에서 달성 조건과 진행률, 획득한 볼을 확인합니다. 조건을 만족하면 볼과 같은 이름의 화면 테마가 자동으로 해금되며 별도 수령 버튼은 없습니다. 기존 성장·도감 기록으로 이미 달성한 업적도 인정하고, 한 번 얻은 보상은 영구 보관합니다.

| 볼 | 획득 조건 |
| --- | --- |
| 몬스터볼 | 기본 제공 |
| 슈퍼볼 | 연결 후 얻은 토큰 100만 개 |
| 하이퍼볼 | 연결 후 얻은 토큰 5,000만 개 |
| 프레미어볼 | 첫 최종 진화 |
| 럭셔리볼 | 이로치 한 종류 이상 발견 |
| 다크볼 | 고스트 타입 세 종류 도감 등록 |
| 마스터볼 | 앱에 있는 61종을 일반 또는 이로치 도감에 등록 |

최초 연결의 과거 로그는 사용량에만 표시하며 토큰 업적에 소급 합산하지 않습니다. 일반·이로치에 같은 종이 있어도 수집 업적에서는 한 종류로 셉니다.

- **개체의 볼:** 부화한 뒤 현재 펫 카드 또는 도감의 개체 선택 아래에서 고릅니다. 다른 개체에 서로 다른 볼을 지정할 수 있고 진화·재실행 후에도 유지됩니다. 해금한 볼은 수량 제한 없이 사용할 수 있습니다.
- **소환·회수:** 홈·트레이·펫 오른쪽 클릭의 **볼에 넣기**로 바탕화면의 친구를 40px 볼로 접어둡니다. 작은 볼을 짧게 클릭하면 다시 나옵니다. 볼도 드래그해 옮길 수 있으며 드래그 후 놓으면 꺼내지 않고 착지합니다. 볼 안에서도 토큰 성장은 계속됩니다. 알은 볼에 넣을 수 없습니다.
- **화면 테마:** 설정의 미리보기 카드에서 고릅니다. 잠긴 테마를 누르면 업적 탭에서 조건을 확인할 수 있습니다. 포켓몬에게 지정한 볼과 앱 테마는 독립적이며 테마는 펫 전용 투명 배경에 적용되지 않습니다.

## 로그 위치와 WSL

| 도구 | 기본 로그 위치 |
| --- | --- |
| Claude Code | `$CLAUDE_CONFIG_DIR/projects` 또는 `~/.claude/projects` |
| Codex | `$CODEX_HOME/sessions`, `$CODEX_HOME/archived_sessions` 또는 `~/.codex` 아래 동일 폴더 |

추가 폴더는 **설정 → 토큰 사용 기록 연결 → 폴더 추가**에서 도구별로 연결합니다. Claude는 `projects` 폴더를, Codex는 `sessions`/`archived_sessions` 폴더를 선택하세요. WSL은 `\\wsl.localhost\배포판\home\사용자\.claude\projects` 등의 Windows에서 접근 가능한 경로를 선택합니다. 배포판이 실행 중이고 경로를 읽을 수 있어야 합니다.

이 앱은 로컬 개발도구 기록을 읽습니다. ChatGPT·Claude 웹사이트의 사용량이나 공식 계정 사용 한도는 조회하지 않습니다.

## 성장

입력·출력·캐시를 중복 없이 합산한 1토큰이 1XP가 됩니다. Codex의 추론 토큰은 출력 토큰에 포함되어 있으므로 다시 더하지 않습니다. 캐시 쓰기는 원본 Codex 파서의 집계 규칙에 따라 별도 합산하지 않습니다.

| 단계 | 빠름 (기본) | 기본 | 느림 |
| --- | ---: | ---: | ---: |
| 부화 | 50만 | 500만 | 1,000만 |
| 첫 진화 | 추가 5,000만 | 추가 5억 | 추가 10억 |
| 최종 진화 | 추가 1억 | 추가 10억 | 추가 20억 |

2단계 계열은 첫 진화가 최종 진화입니다. 앱에서는 진화에 필요한 경험치로 진행하며 원작의 교환·아이템 진화 조건을 적용하지 않습니다. 최종 진화하면 그 모습으로 머물고 이후 토큰과 초과 경험치는 사탕으로 쌓입니다. 다음 알은 직접 선택합니다.

- **포켓몬 선택:** 도감에서 일반·이로치를 따로 선택합니다. 같은 종이 여러 마리면 개체를 고를 수 있습니다. 성장 중인 현재 형태는 토큰으로 자동 성장하고 사탕도 먹일 수 있습니다. 이미 진화한 이전 모습은 완성 상태를 유지하면서 토큰을 사탕으로 적립합니다.
- **성장 보관:** 포켓몬과 미완성 알의 진행률을 각각 보관합니다. 선택을 바꿀 때 아직 반영하지 않은 로그를 먼저 읽어 이전 선택에 반영합니다. 성장 속도를 변경하면 보관 중인 모든 미완성 개체·알의 진행률을 유지합니다.
- **경험치사탕:** 10만 토큰당 1개이며 나머지 토큰도 보관합니다. 사탕을 먹이면 1개당 10만 XP를 더합니다. 최종 진화까지 필요한 XP만 소모하고 남는 가치는 보관합니다. 알과 이미 완성한 형태에는 사용할 수 없습니다.
- **이로치:** 부화할 때 1/64 확률로 결정하며 진화해도 유지합니다. 일반·이로치의 도감 해금과 이미지 캐시는 독립적입니다.
- **타입별 알:** 부화 후보는 계열의 첫 포켓몬 타입으로 결정합니다. 복합 타입 계열은 양쪽 알에서 나올 수 있습니다. 새로 부화한 포켓몬은 별도 개체로 보관합니다.
- **이브이 분기 진화:** 노말 알의 부화 후보에 이브이가 추가됐습니다. 홈 성장 바 옆의 **진화 목표**에서 샤미드·쥬피썬더·부스터·에브이·블래키·리피아·글레이시아·님피아 중 하나를 고릅니다. 원작의 돌·시간·친밀도 조건은 목표 선택으로 대체하며 진화 전까지 바꾸거나 선택을 해제할 수 있습니다. 빠름 기준 5,000만 XP로 진화합니다.
- **진화 대기:** 목표 없이 100%에 도달하면 이브이로 기다리고 초과분·이후 토큰은 사탕으로 쌓입니다. 목표를 고르면 바로 진화합니다. 대기 중에는 사탕을 더 먹이지 않으며 성장 속도를 바꿔도 100%를 유지합니다. 실제로 거친 형태만 도감에 등록하고, 다른 진화형은 새 이브이로 키웁니다. 이로치는 진화 후에도 유지됩니다.

| 알의 타입 | 예시 진화 계열 |
| --- | --- |
| 풀 / 불꽃 / 물 | 이상해씨 / 파이리 / 꼬부기 |
| 노말 / 전기 / 얼음 | 꼬렛 / 피츄 / 대굴레오 |
| 격투 / 독 / 땅 | 알통몬 / 니드런♀ / 모래두지 |
| 비행 / 에스퍼 / 벌레 | 구구 / 캐이시 / 캐터피 |
| 바위 / 고스트 / 드래곤 | 꼬마돌 / 고오스 / 미뇽 |
| 악 / 강철 / 페어리 | 모노두 / 가보리 / 삐 |

한국어 이름·타입·진화 연결은 [PokéAPI](https://pokeapi.co/docs/v2)로 확인한 예시 목록입니다. 전체 포켓몬 목록은 아직 포함하지 않습니다.

이브이의 8개 분기는 [PokéAPI 진화 체인](https://pokeapi.co/api/v2/evolution-chain/67/)을 기준으로 구성했습니다. 기존 저장 상태에는 개체별 실제 진화 경로를 추가하고 이전 성장 데이터를 내부 복구용으로 보관합니다. 사용량·경험치·사탕·도감·설정은 유지하며 과거 토큰을 다시 지급하지 않습니다.

v0.3.x 저장 상태는 첫 실행 때 새 보관 구조로 옮깁니다. 기존 사용량 집계·경험치·도감·설정과 현재 진행률을 유지하며 원래 성장 데이터도 복구용으로 남겨둡니다. 이전 버전의 최종 형태에서 쌓인 성장 완료용 XP는 사탕으로 옮깁니다. 과거 전체 사용량을 사탕으로 소급 지급하지 않습니다.

## 클릭·잡기 문제 진단

실행하면 **로컬 입력 진단 로그**를 자동으로 남깁니다. 클릭이나 잡기가 멈추면 앱을 종료하기 전에 펫을 두세 번 클릭·드래그해 보고 트레이의 **입력 문제 시점 기록**을 선택하세요. **입력 진단 로그 폴더**에서 `pet-input.jsonl`, `pet-input.jsonl.1`, `pet-input.jsonl.2`를 확인할 수 있습니다. Windows 위치는 `%APPDATA%\PokeToken Desktop\diagnostics`, Mac은 `~/Library/Application Support/PokeToken Desktop/diagnostics`입니다.

로그에는 실행 버전, 시각·순서, 펫 주변 마우스 상태, 창의 입력 상태와 클릭·잡기 처리 단계만 남깁니다. 대화·토큰 기록·키보드 입력·다른 창의 제목은 포함하지 않고 자동 전송하지 않습니다. 파일당 최대 약 2MiB, 최신 3개를 보관하며 디스크 기록 실패로 펫이 멈추지 않도록 처리합니다.

- `windows.input`: Windows의 실제 클릭 통과·캡처 상태와 펫 위의 버튼 상태를 120ms 간격으로 관찰합니다. 짧은 클릭은 이 샘플링에서 빠질 수 있으므로 단독으로 클릭 누락을 판정하지 않습니다.
- `windows.message`: 펫 창의 마우스 활성화·누름·해제·캡처 변경 등 정해진 Windows 메시지 이름만 기록합니다. 메시지 원문이나 다른 창 핸들은 기록하지 않습니다.
- `electron.mouse` → `renderer.pointerdown` → `renderer.handler.down` → `ipc.drag`: Electron이 받은 입력, 화면에 전달된 이벤트, 잡기 시작 요청과 메인 상태 변경을 비교합니다.
- `renderer.capture.failed` / `lostpointercapture` / `runtime.error`: 포인터 캡처 예외·취소·화면 오류를 구분합니다. 오류 본문은 저장하지 않습니다.
- 메인·화면의 5초 주기 상태 기록과 잠금·절전·복귀 기록을 함께 남깁니다. Mac에서는 Electron 이후의 단계를 기록합니다.

0.4.5의 실제 재발 로그에서 잠금 해제 후 Windows는 펫 위의 버튼 누름을 감지하지만 Electron의 누름 이벤트가 사라지는 사례를 확인했습니다. 0.4.6은 Windows 복귀 때 기존 펫 창을 폐기하고 새 네이티브 창·화면·입력 연결을 준비합니다. `pet.rebuild-start` / `pet.window-created` / `pet.rebuild-complete`와 창 ID·세대를 기록해 복구 결과를 확인할 수 있습니다. 트레이의 **펫 입력 복구**로 앱 전체를 종료하지 않고 같은 복구를 직접 실행할 수 있습니다. Mac에서는 기존 창의 입력 상태를 다시 설정합니다.

0.4.10은 잠금 없이 발생한 같은 입력 누락도 감시합니다. Windows가 펫 몸 위에서 누름·해제를 관찰했는데 잡기 시작 요청이 없었던 시도가 15초 안에 두 번 이어지면, 버튼을 놓은 뒤 펫 창을 자동으로 교체합니다. 정상 입력의 지연을 기다리고, 다른 앱의 드래그·투명 여백·숨김·이전 창의 신호는 제외합니다. 자동 복구는 최소 30초 간격으로 제한하며 펫 위치·창 위 착지·볼 상태와 기존 성장·설정을 보존합니다. `input.delivery-missed`와 `input.auto-repair`로 감지·복구 시점을 구분할 수 있습니다.

자동 검사는 잠금·절전 알림과 창별 입력 실패를 모의로 발생시키며 실제 창 교체·클릭·잡기·상태 보존을 확인합니다. 별도로 실제 Windows 잠금·해제 후 정상 클릭·잡기를 사용자 확인과 진단 로그로 검증했습니다. 재발하면 앱을 재시작하기 전에 문제 시점을 기록하세요.

## 저장과 네트워크

SQLite 파일과 이미지 캐시는 Electron의 앱 데이터 폴더 아래 `PokeToken Desktop`에 저장됩니다. Windows의 기본 위치는 `%APPDATA%\PokeToken Desktop`, Mac은 `~/Library/Application Support/PokeToken Desktop`입니다. 앱이 닫혀 있을 때 폴더 전체를 복사하면 수동 백업할 수 있습니다.

저장되는 로그 정보는 토큰 수, 시각, 세션/이벤트 식별 정보입니다. 대화 본문과 인증 정보는 저장하거나 전송하지 않습니다. 네트워크 요청은 포켓몬 이미지 다운로드용 `raw.githubusercontent.com`에만 보냅니다. 받은 이미지는 오프라인에서도 사용하며 다운로드 실패 시 이름이 있는 대체 그림을 보여줍니다. 펫은 AI를 호출하지 않습니다.

## 패키징

창 감지는 Windows에서는 앱과 함께 실행되는 숨겨진 PowerShell/Win32 보조 프로세스, Mac에서는 빌드할 때 컴파일하는 Swift/Core Graphics 보조 프로세스로 수행합니다. 창 위치·크기·식별 정보만 메모리에서 사용하고, 창 이름이나 화면 내용은 읽거나 저장하지 않습니다. 보조 프로세스가 중단되면 펫은 바닥으로 내려옵니다.

Windows x64에서:

```sh
npm run dist:win
```

Mac에서 대상 아키텍처에 맞춰 의존성을 설치한 뒤:

```sh
npm ci
npm run dist:mac:arm64
# Intel Mac에서는 npm run dist:mac:x64
```

결과는 `release/`에 저장됩니다. SQLite 네이티브 모듈은 설치·패키징 시 Electron과 대상 아키텍처에 맞춰 재빌드합니다. 소스 빌드가 필요한 경우 Windows에는 Visual Studio C++ 빌드 도구, Mac에는 Xcode Command Line Tools가 필요합니다.

개인용 빌드는 개발자 인증서 서명·공증과 자동 업데이트를 사용하지 않습니다. Mac 앱에는 테스트용 ad-hoc 서명을 적용합니다. Mac은 해당 OS에서 패키징하고 실제 실행을 확인해야 합니다. 빌드 성공만으로 클릭 통과·Spaces·모니터·절전 복귀가 검증되지는 않습니다. 상세한 실기 확인 항목은 [검증 기록](docs/VALIDATION.md)을 참고하세요.

Mac이 없는 개발 환경에서는 저장소 **Actions → Mac test build → Run workflow**에서 `arm64`(M 시리즈) 또는 `x64`(Intel)를 선택합니다. 각 아키텍처의 Mac 러너에서 의존성 설치·테스트·DMG 패키징·패키지 앱 실행을 수행합니다. 결과 파일과 안내문은 실행 결과의 Artifacts에 저장됩니다. [친구에게 전달할 Mac 테스트 안내](docs/MAC_TESTING.md)를 참고하세요.

## 참고 소스

PokeTokenBar의 로그 처리와 성장 규칙을 참고한 별도의 Electron 앱입니다. 원본 저장 파일은 가져오지 않습니다. 코드와 테스트의 원본 고지는 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)에 있습니다. 포켓몬 이미지·명칭의 권리는 해당 권리자에게 있으며 앱 코드는 이미지 권리를 포함하지 않습니다.
